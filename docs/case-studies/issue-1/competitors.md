# GitHub Actions and GitLab CI runner alternatives

Surveyed on 2026-11-20. The comparison covers GitHub and GitLab runners, self-managed autoscalers, hosted runner suppliers and bring-your-own-cloud services. The feature decisions apply to private Linux CI and the issue’s prepaid resale scope. The open-source evidence below comes from reading pinned test contracts. The verification column names what was exercised in Hive Runners.

## Hosted and bring-your-own-cloud products

| Product                               | Documented scope and differentiators                                                                                                                                                                                     |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| GitHub-hosted larger runners          | Fully managed runners, machine sizes, runner groups, autoscaling, static IPs and supported private networking. [GitHub larger runners](https://docs.github.com/en/actions/concepts/runners/larger-runners)               |
| Blacksmith                            | Managed runners, adjustable sizing and concurrency, local caching, Docker build acceleration and job observability. [Blacksmith documentation](https://docs.blacksmith.sh/)                                              |
| Depot                                 | Hosted runners, shared Actions cache, egress filters and colocated remote Docker builders. [Depot GitHub Actions](https://depot.dev/docs/github-actions/overview)                                                        |
| Namespace                             | Configurable runner profiles, multiple operating systems and architectures, cache volumes, and runner telemetry. [Namespace GitHub Actions](https://namespace.so/docs/solutions/github-actions)                          |
| WarpBuild                             | Hosted and bring-your-own-cloud runners, Docker builders, cache, observability, audit logs and snapshot runners. [WarpBuild documentation](https://www.warpbuild.com/docs/ci/what-is-warpbuild)                          |
| Ubicloud managed runners              | Hosted and self-managed paths, arm64, usage and spending controls, Actions caching and SSH job debugging. [Ubicloud GitHub Actions](https://www.ubicloud.com/docs/github-actions-integration/quickstart)                 |
| RunsOn                                | Ephemeral GitHub Actions runners in the customer’s AWS account, selectable machine types and runner images, caching and private networking. [RunsOn documentation](https://runs-on.com/docs/)                            |
| AWS CodeBuild                         | Managed build images with webhook-configured GitHub Actions jobs in the customer’s AWS account. [CodeBuild self-hosted runner guide](https://docs.aws.amazon.com/codebuild/latest/userguide/action-runner-overview.html) |
| Actuated                              | Job-level VM isolation on customer hosts, job SSH debugging, self-managed cache, registry mirrors and monitoring. [Actuated documentation](https://docs.actuated.com/)                                                   |
| Cirun                                 | Managed orchestration for cloud and on-prem runners, configurable labels, idle workloads, fallback runners and custom images. [Cirun documentation](https://docs.cirun.io/)                                              |
| GitLab-hosted runners                 | GitLab-managed, ephemeral job VMs with selectable tags and hardware sizes, including GPU runners for supported tiers. [GitLab-hosted Linux runners](https://docs.gitlab.com/ci/runners/hosted_runners/linux/)            |
| GitLab Docker Autoscaler and Fleeting | On-demand Docker execution against a pool of ephemeral machines using provider plugins for AWS, Azure and Google Cloud. [GitLab Docker Autoscaler](https://docs.gitlab.com/runner/executors/docker_autoscaler/)          |

## Critical capabilities

| Capability                                        | Implementation and verification                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Native Actions workflow and private routing       | ARC handles GitHub scheduling. GitLab’s Helm chart supplies the Kubernetes runner manager. Private scopes, exact workflow labels and tags, runner identity, and credential resolution have fixture coverage. Each CI platform retains job logs and artifacts. Live registered jobs remain open.                                                                                                                                                                                                                                                                               |
| Elastic capacity, spend boundaries and safe drain | A small baseline can grow with demand independently of ARC pod scaling. Pool and provider caps, warm capacity, idle windows, paid activation and two drain observations are configurable. Provider and reconcile fixtures cover transitions, including retirement and contributed capacity. Live lifecycle and isolation remain open.                                                                                                                                                                                                                                         |
| Execution compatibility and tenant isolation      | Built-in process mode for shell and ordinary actions. Opt-in ARC Kubernetes mode for job containers and services. Dedicated trusted hosts can use privileged Docker-in-Docker for Dockerfile actions and Docker builds. Paid execution supports dedicated hosts or opted-in job isolation on shared hosts. GitLab jobs use the Kubernetes executor. Both platforms support explicit NVIDIA GPU allocation. The official Helm templates render these modes. Live job execution remains open. See the [mode and workload table](../../hive-runners.md#bootstrap-and-configure). |
| Operability and operator control                  | CLI and library, validated configuration, generated infrastructure and pull requests, custom runner images, authenticated fleet metrics and a dashboard. Operator-managed inventory supports Linux VPS providers beyond the two built-in APIs. Tests verify generation and API contracts; Docker and Helm are verified locally.                                                                                                                                                                                                                                               |
| Metering, payments and procurement                | Pools charge configured integer cents per rounded minute within the accepted budget. Wholesale matching uses the exact job and isolation profile. Local signed HTTP fixtures cover payment state, refunds, replay after restart and retail/wholesale settlement across two peers. A customer portal and programmatic client expose the same account operations. The latest review waived automated external Stripe operations.                                                                                                                                                |

## Optional product capabilities

- Local cache acceleration, sticky or persistent workspace disks, Docker layer acceleration, registry mirrors and remote BuildKit.
- Expanded runner images and sizes, additional GPU vendors and nested virtualization, browseable images and snapshots, and macOS or Windows execution. The repository’s hosted CI uses Linux.
- Per-job microVM isolation as a workload option, alternate private-network configuration, managed stable egress IPs, and organization SSO and audit integrations.
- Customer SSH or interactive job replay, detailed workflow timing and cost reports, dependency cache analytics, central long-term job logs and managed alert routing.
- Enterprise-hosted GitHub endpoints, CI providers beyond GitHub and GitLab, cloud spot provisioning, operator consoles for deploying new suppliers, settlement payouts, tax, invoicing and a public supplier directory. The documented hub uses explicitly configured partners and prepaid wholesale credit.
