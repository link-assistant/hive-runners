# Issue 1 case study

[Issue #1](https://github.com/link-assistant/hive-runners/issues/1) asks for a private GitHub Actions fleet that can start with a single inexpensive VPS, scale jobs and machines, and support paid capacity and resellers. The issue capture, sub-issue list and discussion snapshots are in [data](data/). The issue, its sub-issue list, and PR conversation and review endpoints showed no additional requirements at the time of capture.

## Primary source research

- GitHub scale-set names can be reused across multiple clusters when assigned to distinct runner groups. GitHub directs operators to set minimum and maximum to zero when draining a queue. [Deploy ARC runner scale sets](https://docs.github.com/en/actions/how-tos/manage-runners/use-actions-runner-controller/deploy-runner-scale-sets)
- GitHub documents different permissions for repository and organization registration, runner-group administration, and signed workflow job deliveries. [ARC authentication](https://docs.github.com/en/enterprise-cloud%40latest/actions/how-tos/manage-runners/use-actions-runner-controller/authenticate-to-the-api) · [Runner groups](https://docs.github.com/en/rest/actions/self-hosted-runner-groups) · [Workflow job webhook](https://docs.github.com/en/webhooks/webhook-events-and-payloads#workflow_job)
- Contabo documents VPS 20 with 6 vCPU, 12 GB of memory and a 200 GB SSD option. Its public API is the basis for the capacity adapter. [Contabo VPS specifications](https://docs.contabo.com/docs/products/cloud-vps/) · [Contabo API](https://api.contabo.com/)
- Hetzner’s adjustment table lists a USD 6.49 monthly cap for CX23 in the relevant low-cost market, excluding public IPv4 and VAT. Its API supports server creation, listing and deletion. [Hetzner cost table](https://docs.hetzner.com/general/infrastructure-and-availability/price-adjustment/) · [Hetzner Cloud API](https://docs.hetzner.cloud/reference/cloud)
- Minikube supports the Docker driver. Kubernetes network policies depend on a compatible enforcement plugin, which is why the playbook selects Calico. [Minikube Docker driver](https://minikube.sigs.k8s.io/docs/drivers/docker/) · [Kubernetes network policies](https://kubernetes.io/docs/concepts/services-networking/network-policies/)
- Stripe recommends fulfillment from events and checking payment status. Session creation and fulfillment are distinct operations. [Stripe Checkout fulfillment](https://docs.stripe.com/checkout/fulfillment) · [Stripe webhooks](https://docs.stripe.com/webhooks)

## Verification sequence

1. Validate generation and provider schemas locally. Lint and render the control-plane Helm chart and the two official ARC charts. Syntax-check the Ansible playbook in the control-plane image.
2. Use the JS acceptance suite to verify the signed request path, durable usage, payments, scope constraints, scale transitions and peer procurement. Use browser checks for responsive navigation and portal authentication.
3. In disposable provider accounts, order and remove a VPS from each provider. Deploy repository and organization pools to registered test repositories. Queue multiple ordinary workflows, observe redistribution and drain, and check that no running job is interrupted.
4. In Stripe test mode, settle a purchase, refund it, deliver the same events to a second configured peer, and verify end-to-end accounting and teardown. Verify the documented isolation boundary using dedicated test machines.

Steps 3 and 4 require cloud accounts, permission to deploy runners to private repositories, and a Stripe test account. The local fixture and schema checks cover steps 1 and 2. No live customer workloads or purchases were used for this case study.
